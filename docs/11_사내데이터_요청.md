# 사내 데이터 제공 요청 (매출·생존 모델용)

요청: 상권 분석 Agent 개발팀 · 2026-11-05

## 1. 목적

출자·심사한 매장의 실제 매출과 운영 결과로 아래 모델을 만든다.

1. 다음 달 매출 예측 (기존 매장)
2. 신규 출점 예상 매출 (지금 모델은 서울시 상권 평균 매출을 정답으로 써서 오차 중앙값이 59%)
3. 폐점 위험 (지금은 인허가 폐업 기록 기반)

모델은 내부 심사에만 쓴다. 매장별 원자료를 외부에 제공하지 않는다.

## 2. 요청 항목

### 2-1. 매장 목록 (매장당 1행)

| 항목 | 필수 | 설명 |
|---|---|---|
| 매장 ID | 필수 | 사내 관리 번호. 사업자등록번호는 받지 않는다 |
| 주소 | 필수 | 도로명 또는 지번, 층 포함 (좌표가 있으면 함께) |
| 업종 | 필수 | 사내 분류 그대로 (대응표는 개발팀이 만든다) |
| 브랜드 | 필수 | 가맹 브랜드명. 개인 매장이면 빈칸 |
| 개점일 | 필수 | YYYY-MM-DD |
| 폐점일·폐점 사유 | 필수 | 영업 중이면 빈칸. 사유는 폐업·양도·이전 구분만이라도 |
| 매장 면적 (㎡) | 권장 | |
| 층 | 권장 | 지하·1층·2층 이상 |
| 월 임대료·보증금 | 권장 | 계약 기준 |
| 심사 결과·등급 | 권장 | 출자 당시 심사 판단 (사후 성과와 비교용) |

### 2-2. 월 매출 (매장 × 월 1행)

| 항목 | 필수 | 설명 |
|---|---|---|
| 매장 ID | 필수 | 2-1과 같은 값 |
| 기준월 | 필수 | YYYY-MM |
| 매출액 | 필수 | 부가세 포함 여부를 함께 알려 준다 |
| 영업일수 | 권장 | 휴업·공사 달 구분용 |
| 결제 건수 | 권장 | 객단가 계산용 |
| 배달 매출 | 권장 | 배달 비중이 큰 업종 |

## 3. 범위와 형식

- 기간: 가능한 한 길게. 최소 매장당 12개월 이상
- 대상: 영업 중 매장 + **폐점한 매장도 포함** (폐점 매장이 빠지면 생존 모델이 왜곡된다)
- 형식: CSV(UTF-8) 또는 Parquet. 파일 2개(매장 목록, 월 매출)
- 전달: S3 경로 또는 사내 공유 폴더. S3라면 읽기 전용 액세스 키 발급 필요

## 4. 개인정보·보안

- 사업자등록번호, 대표자명, 연락처는 받지 않는다. 들어 있으면 적재할 때 버린다
- 저장 위치는 개발 PC의 내부 저장소(접근 제한)이고, 원자료는 학습·검증에만 쓴다
- 화면·API에는 매장별 매출을 내보내지 않고 모델 결과(범위 추정)만 보인다

## 5. 확인 요청

1. 위 항목 중 제공 가능한 것과 불가능한 것
2. 매출의 원천 (POS·카드·보고 매출 중 무엇인지, 부가세 포함 여부)
3. DW 구매 데이터(신한·KB 카드매출, LG U+ 유동인구 백업분)의 계약 종료 후 학습 사용 가능 여부 (L-4)
