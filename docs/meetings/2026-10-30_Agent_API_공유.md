# Agent API 진행 공유 (2026-10-30)

지난 회의에서 정한 컨셉("로드뷰 + 위치 → 출점·출자 적합도 점수, 참고용")을 바탕으로 API 명세와 모델 1차 버전을 만들었다. 이 문서는 **확인과 결정이 필요한 것** 위주로 정리했다. 세부 내용은 [08_API_명세](../08_API_명세.md)에 있다.

## 1. 한 줄 요약

공공데이터만으로 **점수(생존 확률 중심)는 쓸 만한 수준**이 나왔다. 하지만 **매출 예측은 범위로만 제공 가능**하다. 매출 정확도를 올리려면 카드매출 데이터 구매가 필요하다.

## 2. 이번에 정한 것

| 항목 | 내용 |
|---|---|
| 이미지 | 카카오맵 로드뷰 캡처 (최대 4장). 기존 PoC(storecast)의 판독 방식 재사용 |
| 인프라 | **DW 없이도** 동작하도록 설계. S3에 데이터를 두고, 서비스용 DB는 PostgreSQL. 기존 DW 데이터는 S3로 백업 중이며 추가만 하면 된다 |
| Swagger | 초안 완성. 엔드포인트 6개 (평가 요청·조회, 리포트, 대화, 제공 범위 조회, 업종 검색) |
| 응답 원칙 | 모든 수치에 출처와 신뢰등급(A 실측 / B 검증된 계산 / C 오차 큰 추정)을 붙이고, "참고용" 고지를 단다 |

## 3. 동의가 필요한 것 — 요청 항목 2개 추가

| 추가 항목 | 왜 필요한가 | 없으면 |
|---|---|---|
| **희망 업종** | 점수와 매출은 "이 자리에서 **이 업종**"이 정해져야 계산된다 | 상호명이나 간판으로 추정하고 신뢰도를 낮춘다 |
| **매장 면적(㎡)** | 폐업 예측에서 가장 영향이 큰 요소로 확인됐다 | 위치 정보만으로 예측하고 정확도가 떨어진다 |

둘 다 필수는 아니고 **"넣으면 결과가 좋아지는 항목"**으로 둔다.

## 4. 결과물별 수준

| 결과 | 수준 | 설명 |
|---|---|---|
| 종합 점수 | ◎ | 중심은 "이 자리에서 개업하면 3년 안에 폐업할 확률"이다. 전국 음식점 31.8만 곳의 실제 개업·폐업 기록으로 학습했다. 점수가 가장 낮은 10% 구간은 실제로 73%가 폐업했고, 가장 높은 10% 구간은 19%만 폐업했다 |
| 유동인구 | 서울 ◎ / 전국 준비 중 | 전국 유동인구는 공개 데이터가 없어 지금은 주거·직장인구로 대신한다. 확보 경로는 기존 DW의 LG U+ 백업분(사용 범위 확인)이나 통신사 유동인구 구매(5장 3번) |
| 배후세대·직장인구 | ◎ | 서울은 상권 단위, 전국은 행정동 단위 |
| 경쟁점 | 서울 ◎ / 전국 △ | 전국 점포 데이터는 공공데이터포털 운영계정이 승인된 뒤 수집한다 |
| 매출 예측 | △ | 처음 보는 위치에 대해서는 업종 평균보다 약간 나은 수준이다. 그래서 **"월 ○○~○○만 원" 범위**로 제공하고, 서울은 같은 상권의 실제 평균을 함께 보여 준다. 점포 단위 카드매출(DW 백업분 또는 구매)을 쓰면 범위를 좁힐 수 있다 |
| 로드뷰 판독 | △ | 같은 사진을 두고도 판독 엔진(Claude와 로컬 모델) 간 상권 유형 판정 일치율이 47%였다. 그래서 점수 반영은 10%로 제한한다 |
| 리포트·대화형 | ○ | 위 결과를 근거로 생성한다 |

v0의 생존 예측은 **음식점 업종만** 지원한다. 카페·미용 등은 인허가 데이터 파일만 추가하면 같은 방식으로 확장할 수 있다.

## 5. 결정·확인이 필요한 것

| # | 안건 | 누가 | 비고 |
|---|---|---|---|
| 1 | 요청 항목 2개(업종·면적) 추가 동의 | 회의 | 3장 |
| 2 | 매출을 "범위"로 제공하는 것에 대한 동의 | 기획 | 정확한 금액이 필요하다면 3번이 전제 |
| 3 | 데이터 구매 견적: 전국 유동인구(통신사), 점포 카드매출(카드사) | 경영 | 조건: **학습과 API 응답에 쓸 수 있는지** |
| 4 | DW 계약 연장 여부, 그리고 **백업분을 계약 종료 후에도 학습·API 응답에 쓸 수 있는지** | 경영·DW 담당 | S3 백업 진행 중. 카드매출은 매출 예측 정확도를 올릴 핵심 데이터 |
| 5 | S3 버킷과 AWS 계정 | 인프라 | 데이터 이전에 필요 |
| 6 | 파일럿 사용자 범위 | 기획 | 내부 분석가 5명 내외로 시작하는 안 |

## 6. 다음 단계

1. API v0 구현 완료: 위치·업종 확정 → 지표 집계 → 점수·매출 계산 → 로드뷰 판독 → 요약·리포트. 시연은 `/api/docs`(Swagger)에서 가능하다. 로드뷰 판독과 요약은 Claude API 키를 넣은 뒤 검증한다
   - 예시: 서울 시청 앞 한식 66㎡ → 39점(D). 3년 내 폐업 확률 37%, 반경 300m 안에 한식 73곳으로 평균보다 밀집
2. 생존 예측 업종 확대 (카페 등)
3. 운영계정 승인 후 전국 점포 데이터 수집 → 전국 경쟁점 제공
