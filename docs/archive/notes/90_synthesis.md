# 90. 종합 — 상권 분석 AI Agent에 필요한 정보와 수집 가능 범위

입력: 70_reference_services(레퍼런스 3곳 역분석), 80_data_catalog(소스 카탈로그), 키 검증 결과(`npm run check:keys`, 2026-10-29).
범위: 1차 서울, 이후 전국(유료 데이터 + ETL). 진행 순서 DB → 시각화.

> **업데이트 (기존 DW 반영, 95_existing_dw.md):** 신한·KB 점포 단위 카드매출(2021~2024-06), LG U+ 전국 유동인구, KCB 소득·소비·통근·소호를 이미 보유.
> 따라서 아래 "점포 단위 매출 = 유료 전용", "전국 유동인구 = 유료" 공백은 **2024년 중반까지는 해소**되고, 남은 과제는 **최신화(계약 갱신)와 이용 권리 확인**이다.
> 공개 데이터는 (a) 보유 데이터 최신화 (b) 유료 데이터 공백기 대체 지표 역할로 재정의한다.

## 1. 에이전트가 하는 일 → 필요한 정보

| 에이전트 기능 | 필요한 정보 | 성격 |
|---|---|---|
| A. 정보 제공 (조회·요약·비교) | 점포·업종, 인구·유동, 매출 집계, 임대료·지가, 교통·시설, 개폐업 | 사실 데이터 (RAG/툴 호출) |
| B. 진단 (내 상권/가게는 어떤가) | A + 파생 지표(경쟁도, 점유율, 내점률, 성장성, 안정성, 생존율) | 계산 규칙 — 소상공인365 경영진단 정의 공개, 재현 가능 |
| C. 예측 (여기 내면 얼마 팔까, 살아남을까) | A + **학습 타깃**(점포/상권 매출, 폐업 여부) | 모델 — 타깃 데이터가 관건 |

**결론: A·B는 서울 무료 데이터로 대부분 가능. C의 학습 타깃(매출)은 서울도 '상권×업종 분기 추정치'까지만 무료이고, 점포 단위 매출은 유료(카드사)뿐.** 폐업 예측 타깃은 인허가 폐업일·상가정보 스냅샷 차이로 무료 구성 가능.

## 3. 서울 1차 DB (ETL 1단계)

80_data_catalog §8 기준, 우선순위 순:

1. **기준 차원**: `dim_region`(법정동↔행정동), `dim_trdar`(서울 상권 폴리곤), 공간 크로스워크(상권·행정동·집계구·격자 간 면적/점포 가중)
2. **긴급 스냅샷** (이력 삭제 진행 중): 서울 상권분석서비스 전 계열 CSV, 생활인구 행정동 아카이브(~2026-07)
3. **사실 테이블**: 점포 스냅샷(상가정보 분기 CSV), 상권×업종 분기 지표(추정매출·길단위·상주·직장·개폐업), 생활인구, 인허가 이벤트
4. **부동산·입지**: 필지(PNU·공시지가·용도지역), 건물(폴리곤·건축물대장), 임대동향, 실거래, 지하철·버스 승하차
5. **인구 통계**: SGIS 집계구 인구·가구·사업체, 공정위 프랜차이즈

조인 키: 좌표 → PNU(19) → 법정동(10) → 행정동(8/10, 매핑표) / 건물관리번호(25) / 서울 상권코드 / 집계구 / 격자ID.
내부 표준 좌표계 EPSG:5179(또는 5186), 모든 사실 테이블에 **기준 시점** 컬럼.
저장소 제안: PostgreSQL + PostGIS (공간조인·크로스워크 계산), 원본 파일은 날짜별 raw 보관.

## 4. 결정·확인이 필요한 것

| # | 항목 | 왜 중요한가 |
|---|---|---|
| 1 | **AI 학습 이용 조건 법무 검토** | 공공누리 1유형은 AI 학습 명시 없음(별도 AI 유형 존재). 유료 데이터는 계약에 학습권 명시 필요 |
| 2 | 예측 모델의 학습 타깃 | 서울 무료 타깃 = 상권×업종 분기 추정매출(그 자체가 신한카드×보정 추정치) / 폐업 여부. 점포 단위는 유료 |
| 3 | 서울 생활인구 250m 격자 원자료 확보 경로 | 2026-08 이후 행정동 단위 공백 가능 |
| 4 | 추가 API 신청 | 아파트·연립다세대·오피스텔 실거래가, 인허가(일반/휴게음식점 등), 공정위 가맹사업, 지하철/버스 승하차 |

| 6 | DB 인프라 | 로컬 PostGIS로 시작할지, 클라우드로 바로 갈지 |
