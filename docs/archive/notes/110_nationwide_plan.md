# 110. 전국 확대 — 넥스트 스텝 (초안)

입력: 80_data_catalog, 95_existing_dw, 100_competition_agent_data, API 실호출 결과(2026-10-29)
원칙: **"전국 공통 기반 + 서울 고정밀 + 유료 레이어"** 3단으로 분리하고, 에이전트 도구는 어느 지역이든 같은 인터페이스로 답하되 정밀도·출처를 함께 표시한다.

## 2. 넥스트 스텝 (우선순위 순)

### Step 1. 유료 데이터 계약 결정
지역 간 정밀도 차이를 좌우하는 유일한 변수입니다.
- 신한·KB 카드매출, LG U+ 유동인구, KCB 소득·소호의 **갱신 견적**을 받습니다. 2024-07 이후분과 이후 월 정기 공급이 대상입니다.
- 계약서에 **AI 학습·파생 지표 서비스 제공·재배포 범위**를 명시합니다.
- 비교군: SKT 지오비전(50m 격자), BC카드, 금융데이터거래소·한국데이터거래소 상품.
- 결정 결과에 따라 Step 5가 "유료 데이터 직접 사용"이 될지 "추정 모델로 대체"가 될지 갈립니다.

### Step 2. 전국 공통 기반 ETL (무료, 바로 착수 가능)
| 데이터 | 방식 | 규모(대략) | 주기 |
|---|---|---|---|
| 상가정보 | 분기 CSV 전량 | 약 250만 점포 | 분기 |
| 인허가(음식점 등) | CSV 전량 + API 증분 | 업종별 수십만 | 월 |
| GIS건물통합정보 | SHP 전량 (국가공간정보포털/브이월드) | 약 700만 동 | 분기 |
| 연속지적·개별공시지가·토지특성·용도지역 | SHP/CSV 전량 | 약 3,900만 필지 | 연 |
| 건축물대장(표제부·층별) | 세움터 개방 파일 전량 | 대장 수백만 | 월 |
| 실거래(상업용·아파트·토지) | API: 시군구(약 250) × 월 루프 | 연 수천 호출 | 월 |
| R-ONE 임대동향·권리금 | API | 상권 수백 개 | 분기 |
| SGIS 집계구 인구·가구·사업체 + 집계구 경계 | API + 경계 파일 신청 | 집계구 약 10만 | 연 |
| 공정위 가맹정보 | API | 브랜드 약 1.2만 | 연 |
| 소상공인 상권영역 | API | 약 1,200 | 분기 |

- 규모는 대략치입니다. **전량은 파일, API는 증분·검증용**으로 씁니다. 공공데이터포털 개발계정 한도는 일 1만 건이라, 필요한 API는 **운영계정 전환을 신청**합니다.
- 원본은 `기준월`별로 보관합니다. 서울 사례처럼 과거 이력이 삭제되는 경우에 대비하는 것입니다.

### Step 3. 전국 공통 공간 프레임
- 기준 단위를 **국가표준격자 100m(국토지리정보원 코드)**로 정합니다. DW `biz_datadam` LTTC 상품이 이미 이 코드를 씁니다. 250m 격자(서울 생활인구 전환 단위)와는 상위·하위 관계로 맞춥니다.
- 크로스워크 테이블: 격자 ↔ PNU ↔ 건물관리번호(25) ↔ 법정동(10) ↔ 행정동(10/8) ↔ 집계구 ↔ 상권(서울·소상공인·R-ONE·자체). 각 관계에 면적·점포 가중치를 둡니다.
- 행정동 분·합 이력은 **기준일 버전으로 관리**합니다.
- 업종 마스터: 상가정보 247 ↔ 서울 서비스업종 ↔ 공정위 ↔ 신한 ↔ KSIC (100번 문서 Step 3과 같음).

### Step 4. 저장소·인프라 결정
- 전국 규모(필지 약 3,900만, 건물 약 700만, 격자 수백만, 월별 시계열)에서는 공간 조인 성능이 관건입니다.
- 기존 DW가 **BigQuery(GEOGRAPHY)**이고 2026.6~9 이관 계획이 있으므로, 이관 목적지에 맞추는 것을 우선 검토합니다.
- 웹 서비스용 빠른 조회(타일·반경 질의)는 별도 서빙 계층을 둡니다. 예: PostGIS 또는 사전 생성 벡터타일.

### Step 5. 공백 지역 추정 모델 (유료 데이터 범위 밖)
- **학습**: 매출·유동이 있는 곳(서울 공개 데이터 + DW 2021~2024 전국 카드·유동)을 정답으로 씁니다. 입력은 **전국 공통 특성**만 씁니다(점포 구성, 인구, 지가, 건물, 교통, 개폐업).
- **보정**: 서울 추정매출과 DW 신한 점포 매출을 서울에서 맞대어 비교해 스케일 보정계수를 만듭니다.
- **산출**: 격자×업종 추정매출·유동 지수를 만들고 **신뢰등급**을 함께 표시합니다. 데이터 출처가 직접 관측인지, 보정인지, 추정인지 구분합니다.
- 기존 `ibk_score`, `store_closure` 정의를 재사용하고 입력만 최신화합니다.

### Step 6. 단계적 확장
| 단계 | 지역 | 근거 |
|---|---|---|
| 1 | 서울 (현재) | 공개 데이터 최다 |
| 2 | 경기·인천 | 수도권 통근 연계(KCB 통근 OD), 지하철 데이터 일부 공유. 지자체 상권 데이터 존재 여부 확인 필요 |
| 3 | 부산·대구·대전·광주·울산 | 교통공사 데이터, 부산 생활인구 |
| 4 | 그 외 시군 | 공통 기반 + 추정 모델 |

단계마다 **검증 체크리스트**를 돌립니다. 점포 수 대조(상가정보 vs 인허가), 좌표 정합(EPSG 변환), 추정치와 DW 실측의 오차, 기준월 최신성.

### Step 7. 운영
- 수집 스케줄러(월·분기), 실패 재시도, 원본·가공 버전 관리
- 출처·기준시점 메타데이터를 에이전트 응답까지 전달
- 법무: 공공누리 유형별 이용 범위, 크롤링 원천 제외, 개인정보 컬럼 제외 (security.md S11·S12)

## 4. 저장 구조 — 레이크 + 서빙

```
data/lake/raw/{source}/{기준일}/...      원본 그대로(JSON·CSV·SHP), 불변, 재호출 없이 재처리 가능
data/lake/std/{table}/{partition}=…/     표준화(UTF-8, WGS84, 컬럼명 snake_case) Parquet
serving DB (지금 SQLite → PostgreSQL+PostGIS)  앱·에이전트 조회용 최신본과 집계
```
- PostgreSQL은 **서빙 계층으로 적합**합니다. 원본 이력·대용량 시계열(필지 3,900만, 월별 스냅샷 누적)을 담는 레이크 역할까지 맡기면 비용·운영 부담이 커집니다.
- 레이크는 로컬 폴더 → 이후 S3/GCS로 옮깁니다. 분석 엔진은 DuckDB(로컬)나 BigQuery(기존 DW, 외부 테이블)를 씁니다.
- 원칙: **API 응답은 반드시 raw에 먼저 저장하고 서빙 DB는 언제든 raw에서 다시 만들 수 있어야 합니다.** 이렇게 하면 "갈아엎기"가 API 재호출이 아니라 로컬 재처리가 됩니다.

## 5. 증분 적재 전략

공공데이터 대부분은 진짜 CDC(변경분만 제공)를 지원하지 않습니다. 대신 **기준기간 파티션 교체**로 사실상 증분처럼 운영할 수 있습니다. 전체를 갈아엎는 것은 작은 기준 테이블뿐입니다.

| 소스 | 제공 방식 | 적재 방식 | 비고 |
|---|---|---|---|
| 상가정보 | 분기 전체 스냅샷. `storeListByDate?key=20260630`(분기 기준일)이 전국 2,772,467건을 행별 `변경구분`과 함께 반환. 다른 날짜는 NODATA | 분기 스냅샷 적재 → 이전 분기와 `bizes_id` 비교로 신규·변경·소멸 도출 | 개폐업 이력은 우리가 만들어야 함 |
| 인허가 | CSV에 `데이터갱신구분(I/U/D)`·`데이터갱신시점`·`최종수정시점` 있음 | **진짜 증분 가능**: 갱신시점 이후 행만 `mgt_no` 기준 UPSERT | 업종별 파일 |
| 실거래(상업·아파트) | 계약월 단위, 신고기한 30일·해제 신고로 과거 월이 바뀜 | 최근 3개월 파티션(구×월) 매월 삭제 후 재적재 | 해제 여부 컬럼 보존 |
| 서울 상권분석 | 분기 단위, 일부 서비스는 분기 필터 무시 | 최근 2개 분기 교체(추정치 보정 대비) | 서울 전용 |
| 생활인구·지하철 일별 | 일 단위 추가 | 날짜 파티션 추가, 최근 7일 재적재(지연 반영) | |
| R-ONE | 분기·연, 과거 지수 수정 가능 | 통계표 단위 전체 교체 | 작음 |
| 공정위 | 연 단위 | 연도 파티션 교체 | |
| SGIS | 연 단위 | 연도 파티션 교체 | |
| 법정동코드 | 현행 목록(폐지 포함) | 전체 교체 + 변경 이력 보존(유효기간 컬럼) | 행정동 분·합 대응 |
| 지적·공시지가·건물(파일) | 월·연 전체 파일 | 스냅샷 단위 교체. 이력은 레이크 raw에 보존 | 서빙 DB에는 최신본만 |
| 유료(카드·통신) | 월 배치 파일 | 월 파티션 추가 | 계약 조건 따름 |

- 공통 키: 모든 사실 테이블에 `src_period`(기준기간)와 `loaded_at`을 둡니다. 교체는 `DELETE WHERE src_period IN (…)` → `INSERT`를 한 트랜잭션으로 묶습니다.
- 스냅샷 비교(상가정보·건물)는 행 해시로 변경을 감지해 `*_history` 테이블에 SCD2 형태로 쌓습니다. 경쟁점 개폐업 추세(Q6)의 원천이 됩니다.

## 6. 바로 할 수 있는 것 vs 결정이 필요한 것

| 바로 착수 (결정 불필요) | 결정 필요 |
|---|---|
| 서울 상권분석 전 계열 스냅샷 | 유료 데이터 갱신·학습 권리 (Step 1) |
| 전국 상가정보·인허가 CSV 적재 | 저장소: DW 이관 목적지 vs 별도 PostGIS (Step 4) |
| 공정위·R-ONE·실거래 API 수집기 | 공공데이터포털 운영계정 전환 신청 |
| 업종 마스터·공간 크로스워크 설계 | 확장 순서 확정 (Step 6) |
