# 70. 레퍼런스 서비스 지표 역분석 (소상공인365 · 오픈업 · 빅밸류)

- 작성일: 2026-10-29
- 목적: 상권분석 AI Agent가 쓰거나 보여줘야 할 지표를 정하고, 레퍼런스 3개 서비스가 **어떤 지표를 / 어떤 공간·시간 단위로 / 어떤 원천에서** 제공하는지 공개 자료로 정리. 결과는 `80_data_catalog.md`(지표→소스 매핑·수집 가능성)의 입력이 된다.
- 방법: 공개 웹페이지·FAQ·공지·공개 문서(docs)·기사만 사용. 로그인·회원가입·인증 우회 없음.
  - 소상공인365는 SPA라 본문 텍스트가 HTML에 없다. 그래서 **공개 정적 JS 번들**(`https://bigdata.sbiz.or.kr/assets/*.js`, 로그인 없이 누구나 받는 파일)에 들어 있는 안내 문구와 데이터 출처 표를 읽었다. API는 호출하지 않았다.
- 표기:
  - **(추정)**: 원문에 명시되지 않아 내가 추론한 내용
  - **(2차)**: 블로그 등 비공식 출처
  - `[S#]`: 아래 "출처 목록"의 번호

### 1-c. API / B2B / 가격
- 서비스 이용 자체는 무료다. 사이트 고지: "상업적 목적이 아닌 개인적 용도로만 사용 가능. 보도·교육·연구 목적이면 국가데이터처 자료 이용" [S3].
- 공공데이터포털의 '소상공인365 상권분석' 파일데이터는 PDF 리포트 1건뿐이고, 사이트에서 직접 출력하라고 안내한다 [S15].

### 1-d. 방법론 메모
- 추정매출은 카드사 데이터 기반의 "추정"이며 점포 면적·입점 위치 등에 따라 달라질 수 있다 [S6]. 보정 산식은 비공개다.
- 비교용 참고: 서울시 상권분석서비스(골목상권)는 산식을 공개한다 [S16].
  - 추정매출 = 카드결제금액 ÷ 카드보정비율 (보정비율은 지역·업종·카드사별)
  - 카드사: BC·KB·신한
  - 생활인구: 서울시·KT
  - 길단위 유동인구: 10m 길 / 50m 셀
  - 직장인구: SKT, 50m 셀
  - 소득분위: 건강보험공단, 50m 셀
  - 임대시세: 행정동
  - 공식으로 제시된 산식: 개·폐업률, 1·5년 생존율, 평균영업기간, 환산임대료 = 보증금×12%÷12 + 월세

  소상공인365도 비슷한 보정 구조일 가능성이 높다 **(추정)**.
- 경영진단 지표는 모두 "경쟁권" 기준의 비율·증감률 파생 지표다 [S5]. 경쟁권 반경을 정하는 규칙은 공개되지 않았다.

## 2. 오픈업 (OPENUB, ㈜핀다)

### 2-a. 핵심 기능 / 제품
- **오픈업 (B2C, 웹)**: 기본 기능은 무료이고, 상세 매장 보고서는 크레딧으로 연다 [S20][S21].
  - 크레딧: 보고서 1회 조회에 1크레딧, 조회 후 12개월 열람. 매월 무료 크레딧이 지급되고 유료 크레딧은 1년간 유효 [S21][S22]
  - 상권 만들기: 원형 / 사각형 / 다각형
  - 빠른상권: 반경 150m / 300m / 600m / 1.5km, 사용자 지정 반경, "상권맞춤"
  - 업종필터: 음식 / 소매 / 서비스 / 오락 / 교육 / 숙박 + 세부업종
  - 창업계산기, 매장보관함, 대출비교 [S20]
  - 시군구별 공개 보고서 페이지: 예) `/region/11110` 종로구 [S23]
- **오픈업 프로 (B2B, 프랜차이즈 본사용)**: 2025-09 무렵 출시 [S24][S25].
  - 2018년 이후 월별 매출을 무제한 조회
  - 입지 데이터를 읽고 요약·브리핑하는 AI 분석 에이전트 포함
- 종료된 기능 [S24]:
  - 내 매장 (실매출 등록): 2025-10 종료
  - 배민 깃발 최적화: 울트라콜 폐지로 종료
  - 고객 탐색(베타, 히트맵): 종료. 정식 버전은 추후 예정

### 3-d. 방법론 메모
- **점포 매출 예측 (기술블로그)** [S56][S57]
  - 이종 그래프로 구성: POI(점포), 건축물, 100m 격자 배후지
  - 격자 노드 속성: 인구, 세대, 소득, 직장인, 교통, 토지이용
  - 엣지
    - 점포↔건물: 소속
    - 건물↔건물: 100m 인접
    - 격자↔격자: 150m 이웃
    - 건물↔격자: 500m 이내, 거리감쇠 가중
  - PyTorch Geometric HeteroData로 변환해 학습
  - 타깃: 점포의 **다음 달 매출**
  - 변형 실험: 300m 이내 경쟁·보완 점포 관계를 추가하고, 격자 대신 상권 권역을 쓰는 버전
- **누수 방지 규칙** [S57]
  - 예측 시점에 공개되어 있던 데이터만 사용 (기준월이 아니라 공표일 기준)
  - 매출은 스냅샷으로 고정하고, 해당 월이 없으면 파이프라인 중단
  - 임대료·건물 상세는 "출처·시점 검증 전이라 후보" 상태
- **좌표 보정** [S57]: 점포 좌표가 신뢰 범위를 벗어나고 소속 건물이 확정된 경우에만 건물 중심점으로 교체한다. 원래 좌표와 보정 여부는 보존한다.
- **AVM** [S44]: 실거래는 전체 부동산의 약 5%뿐이라 주변 시세·트렌드·이력·개별 특성으로 추정한다. 전국 약 2,000만 건을 하루에 산출한다.
- **통합 키 체계** [S41][S44][S58]: 부동산·사업자·상권·금융을 빅밸류 고유 코드로 묶고, 주소 표현을 공간 키로 확정하는 MCP를 운영한다.

### 4-1. 시사점 (80_data_catalog 입력용)
1. **공통 핵심은 "카드 추정매출 + 통신 유동인구 + 사업자 점포"** 세 가지다. 세 서비스 모두 카드사 원천을 쓰고, 매출은 "보정·추정치"라는 점을 명시한다.
   - 무료·공개로 바로 얻을 수 있는 것은 점포(소진공 API)뿐이다.
   - 매출은 공개 집계를 쓰거나 유료 구매가 필요하다. 공개 집계 예: 서울 골목상권 열린데이터(행정동·상권, 분기).
2. **공간 단위**
   - 공공(소상공인365): 행정동, 주요상권
   - 오픈업: 매장·건물 + 사용자 정의 영역
   - 빅밸류: 지점·건물·필지 + 100m 격자

   AI 에이전트용 DB의 **공통 키는 PNU, 건물관리번호(도로명주소 관리번호), 격자 ID, 행정동 코드**로 잡는 것이 유리하다. 빅밸류 docs의 모든 API가 이 키들로 조회한다.
3. **비용 측면 차별화 여지**: 소상공인365에는 임대료가 없고, 오픈업은 부동산원 통계(상권 유형 단위)를 쓴다. 공개 임대동향과 실거래·공시지가를 결합하면 차별화할 수 있다.
4. **점수·등급 산식은 모두 비공개**다. 소상공인365 경영진단은 지표 정의(내점률, 인구집중도, 상권점유율 등)를 공개했으므로 그대로 재현해 볼 수 있다.
5. **개인정보**: 빅밸류의 소유자 정보와 대표자 주민번호 앞자리는 B2B 계약 기반이다. 우리 서비스는 범위에서 제외하는 것이 바람직하다 **(판단)**.

## 5. 확인 못 한 것

- **소상공인365**
  - 간단분석·상세분석 리포트의 전체 항목 목록과 화면 구성. 리포트 화면은 별도 GIS 앱(`#/hotplace/gis`)이라 공개 번들에서 확인하지 못했다.
  - 상세분석의 실제 공간 해상도 (도로 라인 / 건물 / 격자 / 반경 크기)
  - 유동인구 통신사명 (KT / SKT / LGU+), 매출 카드사명
  - 추정매출 보정 산식
  - 입지등급·상권등급·경영진단 종합점수의 가중치·산식
  - 경쟁권 반경 정의
  - 그랜데이터(가명결합)의 내용
  - 데이터 출처 표 버전 차이: 번들 표 기준은 2024.05, 2차 블로그 표 기준은 2026.01 [S14]. 현재 사이트 최신 기준월은 직접 확인하지 못했다.
  - Open API 트래픽 한도: 소진공 안내 1,000건, 포털 10,000건으로 서로 다르다.
- **오픈업**
  - 유동인구를 화면에 제공하는지 여부
  - 공간 해상도의 내부 단위 (격자 사용 여부)
  - 크레딧 유료 가격 (원/크레딧)
  - 오픈업 프로의 지표 목록과 에이전트 기능 상세
  - 외부 API 제공 여부
  - 통신사·카드사 실명. 신한카드 공식 계약만 확인됨 [S25]
  - 임대료의 공간 단위가 부동산원 상권 단위인지 여부
  - 공식 이용가이드(Notion)는 JS 렌더링이라 본문을 읽지 못했다.
- **빅밸류**
  - 카드매출 데이터의 원천 카드사와 커버리지 (전국 여부, 지점 수)
  - 100m 격자 유동인구·거주·직장인구의 원천 통신사·기관
  - 사업자 데이터의 임대료·보증금 원천 (국세청 임대차 정보로 추정했으나 미확인)
  - Data Product / Cube 가격
  - 마켓플레이스 상품별 차감 유닛
  - 카드매출·사업자 API가 마켓플레이스(구독)에서도 제공되는지 여부
  - 상권 솔루션 화면의 예시 수치(예상 월매출 8,500만원, 성공확률 87% 등)는 UI 예시로 보이며, 실제 산출 근거는 확인하지 못했다.
- **공통**
  - 세 서비스 모두 추정매출의 오차율·정확도 지표를 정량 공개하지 않았다. 예외는 오픈업의 "신뢰구간 약 90%" 언급 [S25]이다.
  - 앱스토어 설명은 확인하지 않았다.
