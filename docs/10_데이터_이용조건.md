# 10. 데이터 이용조건과 법률 검토

마지막 갱신: 2026-11-02 (L-1·L-2 내부 심사 한정 결정). 데이터를 새로 들일 때마다 이 표에 이용조건을 적고, 서비스(심사 화면·Agent API)에 써도 되는지 판단한다.

> **요약**
> - **경기도 유동인구(KT 제공)는 공공누리 2유형, 상업적 이용 금지다.** 2026-11-02 결정으로 **내부 심사 서비스에 한해** 실측값과 이를 학습한 추정값을 쓴다 (L-1·L-2, 아래 5장). **실 서비스(외부) 오픈 전에 외부 자문**을 받아 확정한다.
> - 서버는 `DATA_SCOPE=external`로 띄우면 내부 한정 소스를 자동으로 뺀다. 응답·화면에는 해당 값마다 "내부 심사 한정" 표시가 붙는다.
> - 지금 서비스에 쓰는 서울 생활인구는 공공누리 1유형(출처 표시 시 상업 이용 가능)으로 확인했다.
> - 아직 이용조건을 확인하지 않은 소스가 있다(아래 ⚠). 외부 공개 전에 모두 확인한다.

## 1. 상태 표시

| 표시 | 뜻 |
|---|---|
| ✅ | 이용조건을 확인했고 서비스에 쓸 수 있다 |
| ⚠ | 이미 서비스에 쓰고 있으나 이용조건 원문을 아직 확인하지 않았다. 외부 공개 전 확인 필요 |
| 🔒 | 내부 심사 서비스에만 쓴다. 외부 제공(`DATA_SCOPE=external`)에서는 빠진다. 외부 오픈 전 외부 자문 |
| ⛔ | 서비스 반영 금지. 내부 실험·검증에만 쓴다 |

## 4. 운영 규칙

1. ⛔ 데이터는 DB에 적재하되 **API 서버 코드에서 읽지 않는다**. 적재 테이블과 메타(`meta_source`)에 이용조건을 적는다.
2. ⛔ 데이터로 만든 실험 결과(모델·추정값)는 `ml/` 안에만 두고 서비스에 배포하지 않는다.
3. 🔒 데이터는 서버의 `INTERNAL_ONLY` 목록(`web/server/agent/sources.ts`)에 올리고, 읽는 코드는 `internalDataAllowed()`를 먼저 확인한다. 응답의 `provenance[].license`, 지표의 `license`, `warnings`에 "내부 심사 한정"을 적는다.
4. 외부 제공용 서버는 **`DATA_SCOPE=external`** 로 띄운다. 이때 🔒 지표는 null이 되고 점수는 그 데이터 없이 계산된다 (서울 밖 수요 = 인구 50% + 종사자 50%).
5. 새 데이터를 들일 때 이 문서에 먼저 한 줄을 추가한다. 이용조건을 모르면 ⚠로 적는다.
6. 화면·API의 출처 표(provenance)에 제공 기관을 항상 표시한다. 공공누리 출처 표시 의무를 고려한 것이다.
