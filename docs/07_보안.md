# 07. 보안

> **요약**
> - 키는 서버 `.env`에만 두고 로그에서는 `***`로 가린다. 클라이언트로 키가 내려가지 않는다.
> - 기존 DW 명세 문서에 **외부 제공처 계정·비밀번호가 평문으로** 들어 있다. 계정 교체를 권고한다 (D-1 조치 필요).
> - 개인정보 성격 데이터와 크롤링 원천은 에이전트 응답·학습에서 제외한다.
> - 공개 배포 전에 할 일: IP당 요청 제한, 보안 헤더, 대화에 노출된 키 재발급.

## 1. 지켜야 할 원칙

| # | 원칙 | 적용 위치 |
|---|---|---|
| 1 | 키는 서버 `web/.env`에만. 브라우저로 보내는 환경변수(`VITE_`)에 키 금지 | API 서버, ETL |
| 2 | 로그·오류 메시지에서 키를 가린다 | `etl/lib.ts`의 redact, `scripts/check-keys.ts` |
| 3 | 프록시는 정해진 외부 API만 호출. 사용자가 준 URL로 요청하지 않는다 | `server/kakao.ts`, `server/vworld.ts` |
| 4 | 입력 형식 검증 (예: PNU 19자리), 일괄 지오코딩 500건 제한은 서버에서 | API 서버 |
| 5 | 서버에 쿼리 문자열을 받아 실행하는 엔드포인트를 만들지 않는다. 에이전트에도 자유 SQL을 주지 않는다 | API 서버, 에이전트 |
| 6 | 서빙 DB는 읽기 전용 연결 | 에이전트 도구 |
| 7 | 데이터 안의 문장(점포명 등)은 지시로 취급하지 않는다 | 에이전트 시스템 프롬프트 |
| 8 | 배포는 HTTPS 전용 | 배포 |

## 3. 원본 프로그램(XRayMap)에서 확인한 약점과 웹 버전 대응

역분석 과정에서 확인한 내용을 요약 수준으로만 적는다. 키 값이나 악용 방법은 적지 않는다.

| # | 원본의 약점 | 웹 버전 대응 |
|---|---|---|
| S1 | 클라이언트가 SQL 원문을 만들어 서버가 그대로 실행 | DB API 자체를 쓰지 않음 |
| S2 | 지도·지오코딩 키가 프로그램 안에 하드코딩 | 키는 서버에만, 타일도 프록시 경유 |
| S3 | 전 구간 평문 HTTP | HTTPS 전용 |
| S4 | 인증 없는 서버 파일 쓰기 | 서버 파일 저장 기능 없음 |
| S5 | 라이선스·건수 제한을 클라이언트에서만 판정 | 제한은 서버에서 판정 |
| S6 | 전송 데이터 보호를 되돌릴 수 있는 인코딩에 의존 | TLS 사용, 클라이언트에 비밀값 없음 |
| S7 | 업데이트 파일을 HTTP로 받아 실행 | 웹 앱이라 해당 없음 |
| S8 | 서버 SQL 템플릿·설정이 클라이언트로 내려옴 | 설정은 빌드 시 정적 파일 |
| S9 | 프로그램에 담당자 개인정보 포함 | 코드·리소스에 개인정보 없음 |
| S10 | 임의 URL을 받는 프록시 가능성 | 고정 외부 API만 호출 |
